# データ・権限仕様

## scope

ASSISTANTは個人情報と家族共有情報を分離します。

```text
household:family-001
|-- user:user-001 -> personal
|-- user:user-002 -> personal
|-- user:user-003 -> personal
`-- family:shared  -> 明示共有
```

- `personal`: 本人だけが利用する予定、好み、Routine、通知履歴、端末、会話context。
- `family:shared`: 家族予定、共有タスク、共有地点など、明示的に共有された情報。
- householdに所属しているだけでは、他利用者のpersonal dataを読めません。
- family taskはowner、targets、閲覧者、変更権限を別々に持ちます。

## Agent共通記憶との関係

COREの「全Agent共通記憶」は、同じ認証済み利用者・許可scopeの中でAgentを切り替えても
会話contextを共有するという意味です。別利用者のprivate memoryまで共有する意味ではありません。

ASSISTANTはCOREへcontextを渡す前に利用者とscopeを確定し、その利用者が参照できる情報だけを
渡します。Agent切替によって権限が広がることはありません。

## 主なentity

| entity | 主な内容 |
| --- | --- |
| User | stable ID、household、表示名、timezone、locale |
| FamilyShare | 共有範囲、member、role、access policy |
| AssistantProfile | 呼び方、口調、通知量、静音時間、Agent選択 |
| Device | owner、type、capability、priority、last seen |
| Routine | owner、scope、schedule、condition、action、enabled |
| Delivery | target、device、status、attempt、ack、expiry |
| ResultReference | 共通取得結果のID、source type、provider、元URL、observed/published time、expiry、confidence、verification status、evidence |
| NewsSelection | user、ResultReference、順位、選定理由、既読、配信可否 |
| CoreTaskLink | CORE task ID、requester、scope、delivery correlation |

ASSISTANTは共通News itemやCORE Knowledgeを複製して正本にせず、安定IDとprovenanceを
持つ参照を保存します。ASSISTANTが取得を代行する移行期間も、利用者別の選定・既読・
delivery状態と、再利用可能な共通取得結果を論理的に分離します。

## Delivery記録

現行のlocal-first実装は`RENCROW_ASSISTANT_STATE_DIR`、未指定時は
`~/.rencrow/assistant/state`配下の`deliveries.jsonl`へ状態遷移を追記します。
directoryは`0700`、fileは`0600`とし、次だけを保存します。

- `delivery_id`、`trace_id`
- ASSISTANTの`user_id`、source、category、channel
- `pending`、`sent`、`failed`、`uncertain`
- duplicate判定、作成・更新時刻

通知本文、LINE user/group/room ID、Access Token、Channel Secretは保存しません。
同じ`delivery_id`の最新recordを状態正本として読み、`sent`または`uncertain`を自動送信
しません。現行JSONLは単一processのlocal-first MVP用であり、複数processから同時に
書き込む構成へは拡張しません。

## secretと認証

- OAuth token、API key、pairing secretは設定例やGitへ保存しません。
- 静的な非secret設定とsecret storeを分離します。
- Deviceはpairing後に固有credentialを持ち、利用者・household・capabilityと紐付けます。
- credentialをlogへ出しません。監査logにはactor、action、scope、resultだけを残します。
- 利用者削除、端末紛失、家族離脱時にcredentialとsessionを失効できるようにします。

## 時刻と監査

- scheduleは利用者timezoneを保持し、内部時刻と表示時刻を混同しません。
- 予定変更、Routine変更、共有範囲変更、delivery、ack、CORE移譲を監査可能にします。
- 同じeventの再送は同じidempotency keyで扱い、二重発話や二重実行を防ぎます。
- 位置、健康、学校、勤務などのsensitive dataは必要最小限にし、保存期間を設定可能にします。
- PORTAL、CMD、Deviceへsurfaceを変えても、認証済み利用者とscopeを拡大しません。
- `portal-user`、`cmd-user`、`cmd-admin`、`assistant-user`のようなprofile名は概念例です。
  実装では同名設定の有無にかかわらず、capability、scope、modeをserver側でも検証します。
