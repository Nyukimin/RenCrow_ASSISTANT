# システム概要

RenCrow_ASSISTANTは、利用者ごとの生活Routineを決定論的に実行し、適切な端末へ
能動的に届ける個人・家族向けサービスです。

## 製品上の役割

利用者から見たASSISTANTは、家族それぞれに渡せる「可愛い専属アシスタント」です。
設計上は、PUSH機能を持つPersonal / Family Portal serviceです。

ASSISTANT自身をMio、Shiro、Midori、KuroのようなAgent人格にはしません。
通常は専属アシスタントが前面に立ち、必要な場合だけ利用者がAgentを切り替えるか、
ASSISTANTが仕事をCOREへ移譲します。

## 責務分離

```text
利用者
  |
  v
専属ASSISTANT
  |-- 目覚まし、予定、天気、交通、ニュース
  |-- personal / family scope
  |-- PUSH、端末選択、再通知
  `-- 必要ならCOREへTask昇格
             |
             v
       RenCrow_CORE
       Mio / Shiro / Midori / Kuro / その他Agent
```

| component | 主責務 |
| --- | --- |
| `RenCrow_ASSISTANT` | 日常Routine、個人化、PUSH、配信、端末応答、COREへの移譲 |
| `RenCrow_CORE` | Agent対話、Memory、Recall、Knowledge、調査・生成・長時間Task |
| `RenCrow_PORTAL` | Web Viewer、履歴・設定表示、許可された操作 |
| Device client | 音声・表情・画面・振動・入力を端末能力に合わせて実行 |

PORTAL、CMD、ASSISTANTはCOREの周囲にある兄弟moduleであり、縦一列の必須依存では
ありません。共通のChat／IdleChat／event／audio／Task意味論を利用し、入口だけを
Web、terminal、proactive triggerへ分けます。ASSISTANTだけは生活domainの状態を持つ
常駐application serviceです。

## 設計原則

- **生活機能はAgentから独立させる**: Agentやmodelを変更しても目覚ましや通知を壊さない。
- **発火は決定論的にする**: LLMに時刻管理、重複防止、再試行を任せない。
- **情報と伝え方を分ける**: 同じ家族予定を各利用者・端末向けに変換する。
- **個人情報を越境させない**: personal scopeと明示共有のfamily scopeを分離する。
- **複雑さはCOREへ昇格する**: ASSISTANT内に第二のAgent基盤を作らない。
- **端末を薄く保つ**: 取得・判断・予定管理を端末ごとに重複させない。
- **PUSHを第二の会話systemにしない**: Routine通知とCORE応答を同じInteraction output
  として相関し、端末ごとの表現だけを変える。
- **PORTALとCOREを必須にしない**: PORTALが閉じていてもPUSHし、CORE停止中も
  Agentを必要としないRoutineを可能な範囲で継続する。
