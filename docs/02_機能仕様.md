# 機能仕様

## 仕事の3段階

### Assistant Shortcut

利用者に聞かれた時だけ実行する、短時間で完了する定型処理です。

- 「今日の予定は？」
- 「傘はいる？」
- 「いつもの電車は動いている？」

### Routine

時刻または明示条件によりASSISTANTが自動実行し、利用者へPUSHします。

- 平日7時の目覚まし
- 毎朝の予定・天気brief
- 出発前の電車・バス確認
- 雨、予定変更、運休などの状態変化通知

### RenCrow Task

複数工程、生成、継続監視、承認、複数Agent、外部side effectが必要な仕事です。
ASSISTANTが依頼と利用者contextをCOREへ渡し、COREの結果を再び利用者へ届けます。

例:

- 運休が解消するまで監視し、代替経路を調査する
- 家族全員の予定を比較して旅行計画を作る
- ニュースを深く分析してレポート化する

Shortcutは明示確認によりRoutineへ、Routineは複雑化した時にRenCrow Taskへ昇格できます。

## 生活Routine

| Routine | ASSISTANTの処理 | COREへ昇格する条件 |
| --- | --- | --- |
| 目覚まし | schedule、発話、snooze、再通知 | 原則昇格しない |
| 個人予定 | Google Calendar取得、当日分の整理、本人へ配信 | 予定から複雑な計画を作る |
| 家族予定 | Google Calendarのfamily scope取得、対象者別抽出 | 複数人の調整・提案が必要 |
| 天気 | 地点別取得、傘・服装rule、再確認 | 詳細な判断や外部調査が必要 |
| 電車 | 利用路線の運行情報、出発前配信 | 代替経路の比較・継続監視 |
| バス | Web観測から遅延を推定して配信 | parser修復や複雑なroute調査 |
| 一般ニュース | 事前収集、重複除去、配信 | 深い分析や生成 |
| 個人ニュース | 利用者設定による選択、件数制限 | Agentによる高度な選定・説明 |

横断browser sidecarやdata converterは`RenCrow_Tools`を利用し、ASSISTANTへ複製しません。

## Daily Brief

ASSISTANTは利用者ごとのDaily Briefを作れます。

```text
Daily Brief
|-- 個人予定
|-- 閲覧可能な家族予定
|-- 自宅・学校・会社などの天気
|-- 通勤・通学の交通状況
|-- 一般ニュース
`-- 個人向けニュース
```

情報ごとに鮮度が違うため、一括して一度だけ取得しません。

| 情報 | 基本タイミング |
| --- | --- |
| Calendar | 前夜に準備し、朝に再確認 |
| 天気 | 朝に取得し、出発前に再確認 |
| ニュース | 夜間から早朝に事前収集 |
| 個人ニュース | 一般ニュース準備後に利用者別選択 |
| 電車 | 出発15〜30分前 |
| バス | 出発直前に取得し、必要時だけ短周期再確認 |

## PUSHと応答

通知は最低限、次の状態を持ちます。

```text
scheduled -> notified -> acknowledged
                      |-> snoozed -> scheduled
                      `-> missed -> retry / next-device / closed
```

- 同じ通知をevent IDとdelivery IDで追跡し、再接続時の重複を防ぎます。
- 端末が無応答なら、設定された時間後に再通知または別端末へ切り替えます。
- 利用者が応答した後に別端末から同じ通知を繰り返しません。
- 失敗を成功へ丸めず、degraded、expired、missedを区別します。

## 推測情報

バス位置などWeb表示から推測した情報には、結果、確度、観測時刻、更新時刻、根拠を付けます。

```json
{
  "status": "約8分遅れている可能性",
  "confidence": 0.74,
  "observed_at": "07:42",
  "last_updated_at": "07:43",
  "evidence": "車両位置と予定時刻の差"
}
```

ASSISTANTは確度と観測時刻を省略せず、「確定」ではなく推測として発信します。
